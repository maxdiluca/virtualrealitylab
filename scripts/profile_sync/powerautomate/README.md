`flow.template.json` sets the proposed flow state to `Stopped`. `EnableCloudActions`, `EnableExternalDispatch`, and `EnableFailureNotifications` default to `false`. The first switch guards all SharePoint reads and approval notifications; the second separately guards GitHub dispatch; the third separately guards the optional fixed failure message to the same named approver. Approval creation itself sends an external notification when cloud actions are enabled.

`bindings.example.json` lists placeholder parameter values and connection references. Resolve them privately in the authorised tenant; never commit live SharePoint URLs, roots, connection IDs, approver addresses or credentials. The configuration gate fixes the public GitHub target to `maxdiluca/virtualrealitylab`; another target requires separate review and a template change. Bind embedded, owner-controlled connections rather than accepting connections selected by the run-only user. Restrict manual run permission to the designated profile operator. The template JSON uses the classic flow-level `connectionReferences` map and matching `host.connectionName` aliases. Native solution assembly instead maps each alias with `runtimeSource: embedded`, its connector `api.name`, and a `connection.connectionReferenceLogicalName` taken from an actual exported native reference component. An empty draft binding is not a genuine logical reference; never invent its name, ID or component metadata. Verify the tenant designer's current connector input/output shapes before import and activation.

The manual trigger accepts a case-sensitive single `FolderKey`, optional `AvatarFilename` (default `DEFAULT_AVATAR.png`), and stable `SubmissionKey`. It always reads only `ProfileRoot/FolderKey/index.md` and the named image. It does not enumerate folders or read induction/member lists. Folder and image stem must begin with an ASCII letter and then use ASCII letters, digits, `_` or `-`; folder/stem maximum is 80 characters. Image extensions are lowercase `.png`, `.jpg`, or `.jpeg`. The opaque submission key begins with an ASCII letter or digit and has the same character allowlist, with maximum 100 characters. Do not rename or normalise source folders automatically.

The extension gate checks the last dot-separated segment against an exact, case-sensitive `contains` array allowlist. WDL `startsWith` and `endsWith` are case-insensitive and cannot enforce lowercase extensions; the offline evaluator uses those documented semantics and rejects uppercase and mixed-case extensions through the actual stored allowlist expression.

Before running, the operator prepares a private rendered website preview and verifies and privately records the person's separate consent for that exact final preview and the image, completeness of the biography, the website role, and the exact public-only files. The three trigger attestations (`SubjectConsentVerified`, `ImageConsentVerified`, `DispatchIntentReserved`) must be true. These are manual operational gates, not proof of consent collected by software. A generated skeleton or default image alone does not establish readiness. The receiver independently rejects invalid role/front matter, skeletal or incomplete biography, unsafe links/content and invalid image bytes or private metadata. The first receiver release adds new profiles only; a differing existing profile stops as a conflict for human handling.

The flow freezes both file-content base64 blobs before requesting approval from the sole configured `ProfileApprover`; Markdown must survive a lossless UTF-8 decode/re-encode check. The approval includes the exact Markdown and image attachments, has reassignment disabled, and expires after seven days. It accepts exactly one `Approve` response only when the connector's authenticated `responder.email` matches the configured operator (case-insensitive, whitespace trimmed). It then re-reads both named files; any byte difference stops the handoff. The outgoing payload uses the frozen approved bytes, so a change after the re-read cannot substitute unreviewed content. The approval discloses destination path changes only: `index.md` becomes `content/authors/FolderKey/_index.md`, and the selected image becomes `content/authors/FolderKey/avatar.png` or `avatar.jpg` according to its extension. The receiver preserves file contents exactly; it does not rewrite Markdown or re-encode images. A file needing metadata removal must be prepared again and receive fresh consent/approval. Do not broaden approvals to multiple or forwarded recipients.

The Power Automate prefilter requires nonempty Markdown, at most 12,000 decoded characters and at most 21,332 base64 characters (a conservative 15,999-byte UTF-8 boundary), and at most 43,688 image base64 characters (a conservative 32,766-byte image boundary). The receiver permits at most 16,000 Markdown bytes and 32 KiB image bytes. The serialized client payload must be at most 60,000 characters and its UTF-8 base64 at most 80,000 characters, conservatively enforcing the 60,000-byte receiver envelope. Oversized images need a separately prepared and reapproved image; this flow never resizes them.

After approval, `CreateRepositoryDispatchEvent` sends event type `vr-lab-profile-approved-v1` to the configured repository, with exactly these six top-level client-payload keys:

```json
{
  "schema_version": 1,
  "request_id": "synthetic_submission_v1",
  "folder": "Staff_SyntheticPerson",
  "profile_markdown": "<exact approved UTF-8 index.md>",
  "avatar": {"filename": "DEFAULT_AVATAR.png", "content_base64": "<exact approved image base64>"},
  "approval": {"profile_approved": true, "image_approved": true}
}
```

The receiver computes the content digest. Power Automate does not generate a new random request ID on each run. Before a run is allowed, reserve `SubmissionKey` in an institutionally approved private durable ledger for the exact folder, exact Markdown/image file versions, and recorded consent/approval purpose, and record dispatch intent. Keep the same key for reconciliation of the same submission. This template does not implement an automatic source-side ledger. Deployment therefore requires a reviewed manual ledger process or an independently implemented atomic reservation component. Never erase or overwrite a ledger intent to force a retry. A failed or timed-out dispatch may have reached GitHub: stop, reconcile the workflow run, branch/PR and exact receiver digest for the reserved key, then decide recovery. A new version needs new consent/approval and a new ledger reservation.

GET actions permit bounded retry; approval creation, dispatch and optional failure email use `retryPolicy: none`. A failed or timed-out main scope enters a catch scope that emits a fixed minimal error code and, only if explicitly enabled, sends the fixed private operator notice. The notice contains no profile, folder, person, image, payload or connector error text. Source-bearing actions and the trigger mark inputs/outputs secure; deployment must independently verify run-history permissions, retention and tenant DLP policy. Explicit invalid-input, rejected-approval and changed-content gates stop with fixed error codes; they do not send failure email.

A successful connector response yields `queued-unverified`, not `published`. The source flow has no automatic GitHub PR polling/read-back step in this release. Operator follow-up must verify the receiver's workflow result, exact branch/PR contents and allowed paths before treating PR creation as successful; after a human merge, verify the deployed page and image separately. No automatic merge, source deletion, access change or induction action is included. Rollback stops the flow/dispatch capability, preserves uncertain-write evidence, and handles any pending PR under the website owner's review.
